# Requirements: Feature 5.4 — LiveKit Voice Pipeline Worker & Clinic Turn Engine

> Decisions and behaviours, not implementation micro-details. Every requirement must be testable and map to at least one check in `validation.md`.

## 1. Functional Requirements
| ID | Requirement | Validated by |
|:---|:---|:---|
| R1 | **LiveKit-Agnostic Clinic Turn Engine**: `ClinicTurnEngine` in `src/agent/turn_engine.py` must orchestrate each caller turn through: (1) hierarchical trace & FinOps session binding, (2) `InputGuardrail.evaluate()`, (3) `FinOpsController.check_budget()`, (4) XML delimiter wrapping (`wrap_caller_utterance`), (5) `CacheLadder` lookup for eligible read-only queries, (6) `ModelGateway.astream(Stage.DIALOGUE, ...)`, (7) bounded tool-calling loop (`max_tool_rounds_per_turn`), (8) `OutputGuardrail.validate()`, and (9) `CallSession` turn/latency/token/tool recording. | Tier 1 – T1.1, T1.2; Tier 2 – T2.1 |
| R2 | **Caller Tool Allowlist & Session-Scoped Schemas**: The turn engine must enforce an explicit allowlist of the 5 clinic tools (`check_doctor_availability`, `book_appointment`, `manage_appointment`, `search_clinic_knowledge`, `transfer_to_receptionist`) and advertise session-scoped OpenAI tool schemas (`get_session_scoped_tool_definitions()`) where caller phone/identity fields are stripped. Any attempt by the LLM to call a tool outside the allowlist must be rejected without execution. | Tier 1 – T1.3; Tier 3 – T3.1 |
| R3 | **Verified Caller Identity & Unverified Write Interception**: Verified caller identity (`caller_phone`, `caller_name`, `tenant_id`, `branch_id`, `language`) must be extracted strictly from SIP attributes (`sip.phoneNumber` / `sip.trunkPhoneNumber`) or signed LiveKit participant attributes (`caller_phone`, `lang`, `tenant_id`, `branch_id`) and bound via `caller_session_scope`. If `caller_phone` is absent/unverified, read tools (`check_doctor_availability`, `search_clinic_knowledge`, `manage_appointment(action='lookup')`) must still execute, whereas write intents (`book_appointment`, `manage_appointment(action='cancel'|'reschedule')`) must be blocked before any DB call and routed to `transfer_to_receptionist` with a polite localized explanation. | Tier 1 – T1.4; Tier 2 – T2.2; Tier 3 – T3.2 |
| R4 | **Read vs. Write Tool Timeout & Filler Policy**: Read tools taking longer than `session_tool_timeout_ms` (`400ms`) must abort immediately and yield a localized filler (`build_tool_filler_message`). Write tools (`book_appointment`, `manage_appointment` cancel/reschedule, `transfer_to_receptionist`) taking longer than `400ms` must yield a localized filler at `400ms` while continuing execution shielded (`asyncio.shield`) up to `write_tool_hard_cap_ms` (`3000ms`); if the `3000ms` hard cap is exceeded, the engine must trigger receptionist escalation (`transfer_to_receptionist`). | Tier 2 – T2.3; Tier 3 – T3.3, T3.4 |
| R5 | **Medical Emergency & Guardrail Short-Circuiting**: When `InputGuardrail` or `detect_emergency` flags a medical emergency, the turn engine must bypass LLM dialogue generation, invoke `async_transfer_to_receptionist(urgency='critical', ...)`, mark the session emergency flag (`call_session.mark_emergency`), and yield the localized emergency instruction (`build_emergency_message`). When `InputGuardrail` blocks a prompt injection or diagnosis request, the engine must yield the appropriate safe refusal message without calling the LLM. | Tier 2 – T2.4; Tier 3 – T3.5 |
| R6 | **LiveKit `ClinicVoiceAgent` & `llm_node` Override**: `ClinicVoiceAgent` in `src/agent/voice_agent.py` must subclass `livekit.agents.voice.Agent` and override `llm_node(self, chat_ctx, tools, model_settings)` to extract the latest user utterance from `chat_ctx`, run `ClinicTurnEngine`, and yield validated text strings to the LiveKit TTS pipeline. | Tier 1 – T1.5; Tier 2 – T2.5 |
| R7 | **Plugin Factories, Single-Language Call Config & Lifecycle Hooks**: `src/agent/voice_agent.py` must provide `create_stt` (Deepgram `nova-3`), `create_tts` (ElevenLabs `eleven_turbo_v2_5`), `create_vad` (Silero VAD `v4`), `create_voice_pipeline`, and `entrypoint` configuring a single call language (from token/room attribute, default `"ar"`), speaking the initial greeting (`build_greeting_message`), recording barge-in interruptions (`record_interruption`), and persisting the PII-redacted `CallSession` on room close (`async_end_and_persist`). | Tier 1 – T1.6; Tier 2 – T2.6 |
| R8 | **Signed Token CLI (`scripts/generate_token.py`)**: `scripts/generate_token.py` must support `--phone`, `--lang`, `--tenant-id`, and `--branch-id` arguments and encode them as signed participant attributes in the generated LiveKit JWT. | Tier 1 – T1.7; Tier 7 – T7.2 |

## 2. Non-Functional Requirements
| ID | Requirement | Validated by |
|:---|:---|:---|
| NFR1 | **Zero Import-Time Network I/O (`phase-overview.md` P13)**: Importing `src.agent.voice_agent` and `src.agent.turn_engine` must perform zero network requests (clock-skew compensation runs lazily on worker/token execution, never at module import time). | Tier 1 – T1.8; Tier 7 – T7.1 |
| NFR2 | **Barge-In Write Safety & Idempotency (`spec/tech.md` §2.2, §2.4)**: Cancelling the `llm_node` async generator mid-turn (simulating Silero VAD barge-in) while a write tool is running must not corrupt the database transaction; the shielded write either completes atomically or is safely caught by the idempotency store on retry. | Tier 3 – T3.6 |
| NFR3 | **Observability & PII Hygiene (`spec/tech.md` §2.6, §2.7)**: Every turn processed by `ClinicTurnEngine` must emit a hierarchical trace (`trace_id`, nested spans for guardrails, gateway/cache, and tools) with PII redacted before export, and never log raw caller phone numbers. | Tier 2 – T2.1 |

## 3. Constraints (must NOT do / change)
- C1: Must respect all `spec/tech.md` invariants (§1–§10), including `max_tokens=150` per voice turn, 8,000 token/call budget, $10/day cap, XML delimiters around untrusted caller/RAG text, and zero medical diagnosis.
- C2: Must **not** bypass `ModelGateway`, `InputGuardrail`, `OutputGuardrail`, `FinOpsController`, or `HierarchicalTracer` by routing LLM calls directly through `livekit.plugins.groq.LLM`.
- C3: Must **not** accept caller phone numbers from spoken transcript or LLM tool arguments when `enforce_session_caller_identity` is enabled.

## 4. Dependencies & Assumptions
- **Depends on**: Feature 5.1 (`src/agent/prompts.py`, `src/agent/messages.py`), Feature 5.2 (`src/agent/session_manager.py`), Feature 5.3 (clinic-only `TOOL_REGISTRY`), and Phase 4 (`src/ai_core/*`, `src/tools/gates.py`).
- **Assumptions**: LiveKit Agents SDK `1.7.1` (`livekit.agents.voice.Agent` / `AgentSession`) is installed in `.venv` (verified via `uv.lock`).
