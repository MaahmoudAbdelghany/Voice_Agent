## أولاً: ملخص خطة التنفيذ (`plan.md`)

### 1. الهدف ولماذا نبني هذه الميزة (Objective & Why)
- **الهدف**: ترقية محرك البحث في قاعدة المعرفة الطبية (`clinic_kb.md`) من البحث الدلالي الكثيف فقط (Dense Vector) إلى **معمارية استرجاع هجينة (Hybrid RAG)** تجمع بين:
  1. **التقسيم الواعي بالبنية (`Structure-Aware Chunking`)** في `src/rag/ingestion.py`.
  2. **محرك البحث النصي المتناثر (`BM25Index`)** بلغة Python الصرفة داخل الذاكرة في `src/rag/hybrid_retriever.py`.
  3. **دمج الترتيب التبادلي (`Reciprocal Rank Fusion - RRF`)** بثابت $k=60$ لدمج نتائج Qdrant وBM25.
- **لماذا؟**
  - **دقة استرجاع المصطلحات الطبية والأسماء الحرفية**: المتجهات الدلالية وحدها قد تضعف أمام الاختصارات الطبية الدقيقة (`CBC`, `HbA1c`, `ESR`, `CRP`, `DEXA`)، وأسماء الأطباء المحددة (`د. عمرو خالد النجار`، `د. ياسمين عادل إبراهيم`)، وأكواد الخطوط الساخنة (`19876`, `123`).
  - **حل مشكلة اقتطاع الجداول في الملخص الصوتي (220 حرفاً)**: سابقاً كان جدول الأطباء (10 صفوف) أو جدول التحاليل (11 صفاً) يُفهرس كمقطع واحد ضخم (~2,000 حرف)، مما يؤدي لضياع الصفوف المتأخرة عند اقتطاع الإجابة الصوتية. التقسيم لكل صف مع الاحتفاظ برؤوس الأعمدة يجعل كل طبيب أو تحليل مقطعاً مستقلاً جاهزاً للنطق الصوتي المباشر.

### 2. القرارات الهندسية المعتمدة (Design Decisions D1–D5)
| الكود | القرار المتفق عليه | المبرر الهندسي |
|:---|:---|:---|
| **D1** | بناء `BM25Index` (Okapi BM25: $k_1=1.5, b=0.75$) بلغة Python الصرفة مع إعادة استخدام `normalize_query()`. | بدون أي مكتبات خارجية جديدة، سرعة تنفيذ `< 2ms`، وتوافق تام مع بنية Qdrant الحالية. |
| **D2** | تقسيم جداول Markdown (الأطباء، التحاليل، الأشعة) إلى مقاطع مستقلة لكل صف مع عنوان القسم ورؤوس الأعمدة، وتقسيم النصوص الطويلة (`> 800` حرف)، وإبقاء الأسئلة الشائعة (`س/ج`) ذرية. | يمنع اقتطاع بيانات الأطباء والتحاليل في الإجابات الصوتية ويرفع دقة المطابقة. |
| **D3** | الترتيب بمعادلة RRF ($k=60$) مع إرجاع `rrf_score`, `dense_score`, `bm25_score`, `match_sources` ومعايرة `score` في النطاق `[0, 1]` وتصفية كلمات التوقف العامية (`هل`، `عايز`، `سعر`، `كام`). | يحقق متطلب RRF ($k=60$) مع الحفاظ على التوافق الكامل مع `ClinicKnowledgeSearchTool` (`score_threshold=0.35`) ومنع الإيجابيات الكاذبة. |
| **D4** | جعل `HybridKnowledgeRetriever` يغلّف `QdrantKnowledgeRetriever` بنفس الواجهة تماماً، وربطه افتراضياً مع `ClinicKnowledgeSearchTool` و`ingestion_pipeline` عبر `hybrid_search_enabled=True`. | ترقية شفافة دون كسر أي كود أو اختبار سابق. |
| **D5** | مزامنة فهرس BM25 تلقائياً عند `upsert_chunks()` أو عبر `scroll()` الكسول من Qdrant (مع التغذية التلقائية عند `warm_up()` إذا كانت الذاكرة فارغة)، وإبقاء `sanitizer.py` ومحددات XML للميزة 4.4. | يمنع أي اختلاف بين Qdrant وBM25 ويحترم حدود مراحل خارطة الطريق. |

### 3. مجموعات التنفيذ الذرية (Execution Groups)
1. **المجموعة 1**: إضافة إعدادات البحث الهجين في `src/config.py` و`.env.example`، وترقية `parse_markdown()` في `src/rag/ingestion.py` لدعم التقسيم الواعي بالبنية (صفوف الجداول، الفقرات، الأسئلة الشائعة).
2. **المجموعة 2**: بناء `tokenize_for_bm25()`، ومحرك `BM25Index`، ودالة الدمج `reciprocal_rank_fusion()` في `src/rag/hybrid_retriever.py`.
3. **المجموعة 3**: بناء `HybridKnowledgeRetriever` ومزامنته التلقائية وربطه مع `ClinicKnowledgeSearchTool` و`scripts/ingest_clinic_knowledge.py`.
4. **المجموعة 4**: كتابة حزمة الاختبارات الشاملة في `tests/test_hybrid_rag.py` والتحقق من عدم الانحدار.

## ثانياً: ملخص المتطلبات (`requirements.md`)

### 1. المتطلبات الوظيفية (Functional Requirements)
- **R1 (التقسيم الواعي بالبنية)**:
  - تفكيك جداول Markdown إلى مقاطع على مستوى الصف (`chunk_type="table_row"`) تتضمن عنوان القسم + `اسم العمود: القيمة`.
  - الحفاظ على الأسئلة الشائعة (`### س ...`) كمقاطع ذرية (`chunk_type="faq"`).
  - تقسيم النصوص السردية التي تتجاوز `rag_chunk_max_chars` (800 حرف) على حدود الفقرات (`chunk_type="section"`).
- **R2 (محرك BM25 النصي)**:
  - خوارزمية Okapi BM25 بمعاملات قابلة للضبط ($k_1=1.5, b=0.75$) مع تطبيع النص العربي والإنجليزي (`normalize_query`) وحذف كلمات التوقف مع الحفاظ على الرموز الطبية والأرقام، ودعم التصفية المسبقة حسب القسم (`category`).
- **R3 (دمج RRF ومعايرة الدرجات)**:
  - تنفيذ بحث مزدوج (Dense + BM25) ودمج النتائج بمعادلة $\text{RRF}(d) = \sum \frac{1}{60 + \text{rank}(d)}$.
  - إرفاق الحقول `score` (معاير بين `[0, 1]`)، و`rrf_score`، و`dense_score`، و`bm25_score`، و`match_sources` في كل نتيجة.
- **R4 (استرجاع الكيانات الطبية الدقيقة)**:
  - ضمان ظهور الصف المطابق تماماً في المراكز الأولى عند البحث عن اختصارات التحاليل والأشعة (`CBC`, `HbA1c`, `DEXA`)، أو أسماء الأطباء العشرة، أو شركات التأمين (`AXA`, `MetLife`).
- **R5 (المزامنة والتكامل والأمان التشغيلي)**:
  - مزامنة تلقائية عند `upsert_chunks` و`recreate_collection` و`scroll` الكسول، ومفتاح إيقاف `hybrid_search_enabled`، والتدهور الآمن (Fail-Open) إلى البحث الدلالي إذا حدث أي خطأ في BM25.

### 2. المتطلبات غير الوظيفية والقيود (NFRs & Constraints)
- **NFR1 (زمن الاستجابة)**: زمن الاسترجاع الهجين الوسيط `< 100ms` (وضمن ميزانية الأداة `< 400ms`)، وزمن خطوة BM25 + RRF وحدها `< 5ms`.
- **NFR2 & NFR3**: صفر مكتبات خارجية جديدة، وقابلية اختبار كاملة بدون إنترنت (`:memory:`).
- **C1–C4**: عدم كسر واجهات `QdrantKnowledgeRetriever` أو `ClinicKnowledgeSearchTool`، والحفاظ على حارس `is_semantic == False`، وإبقاء `sanitizer.py` ومحددات XML للميزة 4.4.

## ثالثاً: ملخص معايير التحقق والاختبار (`validation.md`)

وفقاً لمهارة التحقق (`validation/SKILL.md`) وبناءً على قدرات المستودع الفعلية (`pytest`, `ruff`, `uv`):
- **المستوى 1 (Unit Verification)**: اختبارات معزولة لتقسيم الجداول والفقرات والأسئلة الشائعة، وتقطيع كلمات BM25 وتطبيع العربية وحذف كلمات التوقف، وحسابات معادلة RRF ($k=60$).
- **المستوى 2 (Integration Verification)**: اختبارات تكامل شاملة مع `clinic_kb.md` وQdrant داخل الذاكرة وFastEmbed و`ClinicKnowledgeSearchTool` للتحقق من استرجاع `CBC`، و`HbA1c`، و`DEXA Scan`، وأسماء الأطباء مثل `د. عمرو خالد النجار` مع ظهور السعر والمواعيد كاملة في الرسالة الصوتية، والمزامنة الكسولة عبر `scroll`.
- **المستوى 3 (Error & Edge-Case Verification)**: اختبار رفض الأسئلة خارج النطاق (مثل سؤال سعر البيتزا مع وجود كلمة "سعر")، واختبار مفتاح الإيقاف `hybrid_search_enabled=False`، واختبار التدهور الآمن عند تعطل BM25، واختبار الاستعلامات الفارغة، واختبار زمن الاستجابة `< 100ms`.
- **المستوى 4 (Regression Checks)**: نجاح جميع اختبارات المراحل السابقة (`test_clinic_rag.py`, `test_knowledge_search.py`, `test_cache_*.py`, `test_model_gateway.py`, `test_clinic_tools.py`, `test_database.py`).
- **المستوى 5 (Build, Lint & Type Checks)**: فحص الكود عبر `uv run ruff check` و`uv run ruff format --check`، مع إعفاء فحص الأنواع (`Type Checking: Not Applicable`) لعدم وجود `mypy`/`pyright` في `pyproject.toml`.
- **المستوى 6 (Manual / Visual Verification)**: غير منطبق (`Not Applicable`) مع تبرير تقني لأن الميزة خلفية برمجية في طبقة الاسترجاع دون واجهة رسومية.
- **المستوى 7 (API / CLI / Application Checks)**: تشغيل أداة الفهرسة والاختبار المباشر:
  ```powershell
  $env:PYTHONIOENCODING="utf-8"; uv run python scripts/ingest_clinic_knowledge.py --recreate --test-query "د. عمرو خالد النجار ومواعيد عيادة الأسنان وتحليل HbA1c"
  ```
